Ch9: VISUAL RECIPES (NO DRAWINGS)
Task-Dependency Graphs (DAG) — Fast Recipe
Goal: draw a DAG + compute metrics (concurrency, critical path, max speedup).
How to Draw
1) Vertex = one task (given by the decomposition).
2) Edge u → v if v needs data produced by u (true dependence).
3) Put tasks of the same “superstep / loop-iteration” on the same level (if synchronous).
How to Compute Metrics
Work W = (#tasks) × (cost per task)
Max concurrency = max #tasks that can run in parallel (max level width)
Critical path L = length of the longest path in the DAG
Max speedup (∞ procs): Smax = W / L
Min #procs to reach Smax ≈ max concurrency
Useful lower bound: Tp ≥ max(W/p, L).

Cannon (p=16) — “How to draw the pictures”
Exam-style: show mapping + communication steps on 16 procs (4×4).
Grid√p×√p = 4×4, processors P(r,c)
BlocksA[r,c], B[r,c], C[r,c] (block size n/4)
Step 0: Initial Skew (alignment)
• Shift A left by row index r (wrap-around).
• Shift B up by col index c (wrap-around).
Steps 1..4: Multiply + Shift
Repeat for s = 0..3:
1) Local multiply: C[r,c] += A_local × B_local
2) Shift A left by 1, shift B up by 1 (circular).
Drawing Trick (avoid re-drawing shifts)
After initial skew + s shifts (q=4):
A at P(r,c): A[r, (c + r + s) mod q]
B at P(r,c): B[(r + c + s) mod q, c]
Write these indices inside each grid cell for each picture.
DNS for 3×3 matrices — “How to draw the pictures”
Goal: show 3D layout + broadcasts + reduction. For n=3, use q=3 ⇒ p=q³=27 procs.
Topology3×3×3 (i,j,k) 3D mesh/torus
Mapping
Processor P(i,j,k) computes partial for C[i,j] with k as “summation index”.
Hold A(i,k) and B(k,j) (block size 1×1 when n=q=3)
Communication / Compute Steps
1) Broadcast A(i,k) along the j-dimension: (i,*,k).
2) Broadcast B(k,j) along the i-dimension: (*,j,k).
3) Local multiply: partial = A(i,k)·B(k,j).
4) Reduce partials along k to sum into C(i,j).
Drawing trick: draw 3 layers (k=0,1,2), each a 3×3 grid; show broadcasts inside each layer and reduction across layers.

If asked to “draw network + write outputs”, you can redraw from this list.
Comparator Notation
Comparator (a,b) ↑ : output min→a, max→b
Comparator (a,b) ↓ : output max→a, min→b
n=4 Bitonic Network (ascending sort)
Stage 1 (make bitonic): (0,1) ↑ and (2,3) ↓
Stage 2 (merge distance 2): (0,2) ↑ and (1,3) ↑
Stage 3 (merge distance 1): (0,1) ↑ and (2,3) ↑
Processors usable: p = n (one item/proc). For p=n: Tp ≈ log²n·(tᶜ+tₛ+tᵥ).
Enumeration Sort on 4 numbers — “how to illustrate”
Recipe (works for any n):
1) All-to-all share values (each proc learns all numbers).
2) Each element computes rank = #{values smaller} (+ tie-break by index).
3) Place element into output position = rank (send to owner via all-to-all personalized).
Rank formula
rank(x_i) = |{j: x_j < x_i}| + |{j<i: x_j = x_i}|
For distinct values: rank(x_i) = #{j: x_j < x_i}.
Max processors (simple version): p = n (one element per proc).
Dijkstra Token Termination — how to “draw steps” fast
What to draw each picture: ring P0→P1→…→P(p−1)→P0, token position+color, proc colors (WHITE/BLACK), idle/busy.
Simulation Checklist
1) Init: token WHITE at P0, all procs WHITE, all busy.
2) When a proc sends work to LOWER ID → proc becomes BLACK.
3) Token becomes BLACK if it passes any BLACK proc.
4) When a BLACK proc forwards token → proc turns WHITE.
DONE when token returns to P0 WHITE and P0 is idle.
Tree-Based Weights — rules + worked scenario
Rule: a processor with weight w splits work → keeps w/2 and sends w/2 with the work.
When child finishes → returns its remaining weight to parent.
DONE when P0 idle and weight(P0)=1.
Worked Example (P0→P1, P0→P2, P1→P3, then finish)
StepActionWeights (P0,P1,P2,P3)
0Start(1, 0, 0, 0)
1P0 gives to P1(1/2, 1/2, 0, 0)
2P0 gives to P2(1/4, 1/2, 1/4, 0)
3P1 gives to P3(1/4, 1/4, 1/4, 1/4)
4P2 finishes → return to P0(1/2, 1/4, 0, 1/4)
5P3 finishes → return to P1(1/2, 1/2, 0, 0)
6P1 finishes → return to P0(1, 0, 0, 0)
If P0 is idle at step 6 and token/weights confirm → termination.
Luby’s Algorithm (MIS) — how to illustrate iterations
Each iteration: assign random numbers → choose candidates → add to MIS → delete candidates+neighbors → repeat.
Per-Iteration Rules
1) Each active vertex v draws random r(v).
2) Candidate if r(v) is strictly larger than all neighbor r(u) (tie-break by ID if needed).
3) Add all candidates to MIS.
4) Remove candidates and all their neighbors from the graph.
If “random generator returns vertex ID”
r(v) = ID(v) ⇒ candidates = local maxima by ID.
Then just pick vertices whose ID is larger than every neighbor ID.
Fast “picture” template (what to show)
• Circle/highlight candidate set
• Mark MIS so far
• Cross out removed vertices (candidates + neighbors)
Stop when no vertices remain. #iterations = #rounds drawn.
How to force exactly 2 iterations (if allowed to choose randoms)
Choose round-1 randoms so that:
• Selected candidates form an independent set.
• After removing candidates+neighbors, remaining graph is non-empty.
In round 2, give remaining vertices highest randoms so they get picked.

2D Transpose FFT (n=16)
Classic view: arrange data as a √p×√p matrix, do FFTs on rows, transpose, FFTs on rows again (former columns).
Case A: p=16 (4×4 grid)
Map index k to grid (r,c): k = 4r + c. Proc P(r,c) holds x[r,c].
Step 1: Each row r computes 4-point FFT on its 4 values.
Step 2: Transpose: send x[r,c] → P(c,r) (all-to-all personalized).
Step 3: Each row (former column) computes 4-point FFT.
Case B: p=4 (2×2 grid)
Each proc holds a block of 4 values. Do 4-point FFTs locally, then transpose blocks between the 2×2 procs, then finish FFTs.
When asked “how many processors”: state which mapping you use (p=16 or p=4) as specified by the question.
0/1 Knapsack DP — task graph recipe
Standard DP table: DP[i,w] for i=0..n (items) and w=0..c (capacity).
Each DP[i,w] depends only on previous row i−1:
• DP[i,w] ← DP[i−1,w]
• If w ≥ w_i: DP[i,w] ← DP[i−1,w−w_i] + p_i
For the specific instance (n=3, c=8, w=[2,3,4])
To draw: make a grid with rows i=0..3 and columns w=0..8; draw 1 or 2 edges from row i−1 into each node (i,w) based on w_i.
Matrix Parenthesization DP — task graph recipe (A,B,C,D)
Tasks are ranges: AA,BB,CC,DD, AB,BC,CD, AC,BD, AD.
Edge: “bigger range depends on its split subranges”.
Dependencies (for 4 matrices):
AB ← AA,BB
BC ← BB,CC
CD ← CC,DD
AC ← (AA,BC) and (AB,CC)
BD ← (BB,CD) and (BC,DD)
AD ← (AA,BD) and (AB,CD) and (AC,DD)
1D Knapsack on CREW PRAM — what to say/draw
Use 2 arrays prev[w], curr[w] so each row update is parallel-safe.
Processors: p = c+1 (one per capacity w).
For each item i (n iterations): all processors compute curr[w] in O(1) from prev[w] and prev[w−w_i].
Tp = Θ(n) with p=Θ(c) processors
Work W = Θ(nc) ⇒ cost pTp = Θ(nc) ⇒ cost-optimal
