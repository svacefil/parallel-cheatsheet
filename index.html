Ch2: CUSTOM DERIVATIONS
Prefix Sum (n/p > 1)
Phase 1Local prefix: (n/p-1)·tₐdd
Phase 2Parallel: logp·(tₛ+tₐdd)
Phase 3Update: (n/p)·tₐdd

Exact time breakdown (matches exam wording)
Assumptions: p=2^d hypercube, each processor holds n/p numbers (n/p integer > 1). Communication per step is a unit-length message (one number). Notation mapping: exam uses t_add (add), t_s (send 1 number). 
Phase A (local prefix):      (n/p - 1) · t_add
Phase B (cube scan of sums): log2(p) · ( t_s + t_add )
Phase C (offset add):        (n/p) · t_add
TOTAL: (2n/p - 1)·t_add + log2(p)·(t_s + t_add)
Meaning: Phase B does log2(p) neighbor exchanges (dimension by dimension). Each step sends one partial sum and adds it (hence t_s + t_add).
Prefix Sum (p=n)
Tp = logn·(tₛ + tₐdd)
S = n / (logn·(tₛ+tₐdd))
Cost = n·logn → NOT cost-optimal (W=n)
Scatter Optimality on Linear Array (tₛ=0)
Setup: scatter from root to p-1 other processors on a 1D linear array (pipeline). Each destination receives a message of size m (words). Total data M = p·m.
T_pipe = (p-1)(tₛ + m·tᵥ)
If tₛ=0: T_pipe = (p-1)m·tᵥ = tᵥ·M·(p-1)/p
Lower bound (bandwidth)
All p-1 messages must cross the first link out of the root ⇒ at least (p-1)m words cross that link. With tₛ=0, time per word is tᵥ ⇒ any algorithm needs time ≥ (p-1)m·tᵥ.
Conclusion: pipeline achieves the lower bound ⇒ asymptotically optimal.

Full step derivation (what each term means)
Assume p processors in a 1D neighbor topology (line / ring). Each processor holds m = n/p keys.
Algorithm:
0) Local sort of m keys.
1) Repeat p phases (odd/even): each phase, each processor exchanges its m keys with one neighbor and performs compare-split (merge 2m, keep half). 
Local sort (per proc):      Θ(m log m)

One phase (per proc):
  comm (send+recv m words): tₛ + m·tᵥ
  compute (merge/split):    Θ(m)

Total p phases:
  T_comm  = p·tₛ + p·m·tᵥ = p·tₛ + n·tᵥ
  T_merge = Θ(p·m) = Θ(n)

So: T_p = Θ((n/p)log(n/p) + n + p·tₛ + n·tᵥ)
Isoefficiency + cost-opt (common exam answer)
Using odd-even network work W = Θ(n²): Overhead To ≈ p(p·tₛ + n·tᵥ) = Θ(p² + pn) (ignoring constants). 
W = K·To:
n² = K(p² + pn)  ⇒  n = Θ(p)
Isoeff: W = Θ(p²)

Cost-opt: require p·T_p = O(n²) ⇒ p = O(n)
Scalability: isoeff Θ(p²) ⇒ needs quadratic growth of work to keep efficiency constant.

Parallel Quicksort (shared-address space)
Goal: derive Tp and isoefficiency (expected / average-case).
Model: shared memory with p processors (barriers instead of explicit message passing).
Core idea (one partition level)
1) Choose pivot (random / median-of-samples).
2) Each processor scans ≈ n/p elements, counts how many go left/right.
3) Do prefix-sum over the p counts to get write offsets (needs a barrier).
4) Each processor writes its elements into the correct side.
Per-level time
Scan + move elements:   Θ(n/p)
Prefix-sum on p counts: Θ(log p)
Barrier/sync:           Θ(log p)  (often absorbed)
So: T_level = Θ(n/p + log p)
Total parallel time (expected)
Expected recursion depth is Θ(log n) for good pivots.
T_p = Θ((n/p)·log n + log n·log p)
Isoefficiency + scalability
Expected sequential work W = Θ(n log n). Overhead comes mainly from prefix-sums / barriers each level: To = p·T_p − W = Θ(p·log n·log p). 
W = K·To:
n log n = K·p log n log p
⇒ n = Θ(p log p)
⇒ W = Θ(p log p · log(p log p)) ≈ Θ(p log² p)
Cost-opt upper bound (rule of thumb): p log p = O(n) ⇒ p = O(n / log n).

Bitonic Sort (compare-split, p=4)
Setup: n=8, p=4 ⇒ each proc has m=n/p=2 elements.
Compare-split primitive:
Two procs exchange their m-elements blocks, merge 2m elements, then split:
+ (increasing): lower-rank keeps smaller half, higher-rank keeps larger half.
− (decreasing): lower-rank keeps larger half, higher-rank keeps smaller half.
(Keep local order consistent with the comparator direction.)
Network for p=4 (decreasing output)
Stages: k=2 then k=4. Steps (j): 1, then 2, then 1.

Step 2 (k=4,j=2):  P0 --(−)-- P2     P1 --(−)-- P3

Scatter optimality proof (tₛ=0)
Scatter on linear array: root has p messages (each size m), one for each processor.
Pipelined scatter time:
T = (p-1)·(tₛ + m·tᵥ)
Case tₛ=0: T = (p-1)·m·tᵥ (matches exam form t_w·m·(p-1) if tᵥ≡t_w)
Meaning of each term
• tᵥ (or t_w) = per-word transfer time (bandwidth cost)
• m = message size (words per processor)
• (p-1) = number of messages sent (one to each non-root processor)
Why this is asymptotically optimal (tₛ=0)
Lower bound: consider the first link out of the root. All other processors need their m words, so at least (p-1)m words must cross that link.
With startup 0, bandwidth-limited link time ≥ (p-1)m·tᵥ.
Algorithm achieves this bound ⇒ asymptotically optimal.
All-to-all broadcast on 2D mesh
All-to-all broadcast (allgather): each processor broadcasts its own message of size m to all processors.
2D mesh √p×√p derivation: do it in 2 phases (rows then columns).
Phase 1: allgather within each row
Each row has √p processors. Use ring allgather (√p-1 steps), message size m each step.
T_row = (√p-1)·(tₛ + m·tᵥ)
Phase 2: allgather within each column
After Phase 1, each processor holds √p messages ⇒ total size √p·m. Allgather that along the column.
T_col = (√p-1)·(tₛ + √p·m·tᵥ)
Total + simplification
T = T_row + T_col = 2(√p-1)tₛ + (p-1)m·tᵥ
Because (√p-1)(√p+1)=p-1 ⇒ bandwidth term collapses nicely.
Asymptotic: Θ(√p·tₛ + p·m·tᵥ)
